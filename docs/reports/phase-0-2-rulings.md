# Phases 0–2: implementation rulings

Every deviation from the implementation plan, and every judgement call made
where the plan and the spec did not decide the matter, with the reasoning and
what it costs if the call was wrong. Four decisions were large enough to need a
record of their own and have one ([ADR 0001–0004](../decisions/)); the phase
reports carry the measurements and the acceptance criteria. This file is the
remainder: 117 rulings made while building phases 0–2.

It exists because the reasoning is the part that does not survive in the code.
A reader who wonders why something is shaped the way it is should find the
answer here rather than reconstructing it from a diff.

**How to read a ruling.** Each one states what was decided, why, and — where
one was identified — the cost if the decision turns out to be wrong. "Cost if
wrong: none identified" means exactly that, not that the decision is certain.

## Task 17: Streaming STT engine

- built the engine on Moonshine's native streaming API rather than the brief's re-transcription loop — the brief called `moonshine_voice.load_model`, which does not exist, and re-transcribed the whole utterance per block, which is spec 5.3's fallback for a library *without* a streaming API where ADR 0001 found one; measured before rejecting (batch transcribe 2s→0.48s, 4s→1.32s, 8s→2.06s, so a block 8 s into a sentence needs ~20× its own duration in compute) — cost if wrong: the engine's seam is the stream API's shape, so a future Moonshine that changes it breaks `StreamingSttEngine` rather than one `transcribe` callable.
- constructor takes `new_stream: Callable[[], Any]` instead of the brief's `transcribe` — a Moonshine stream accumulates one transcript for its lifetime, so a session must get its own, and building it lazily on the first block keeps `load_engine` (which runs at daemon start) from leaving a stream open through every session the user never begins — cost if wrong: one more callable in the signature than the brief specified.
- added `reset()` to the `SttEngine` protocol, both existing engines, and the daemon's `_discard` — spec 9.4's cancel had no way to clear engine state, and spec 5.3 keeps one engine for the daemon's whole life, so a cancelled session leaked its audio and transcript into the next; proved RED first with a daemon test where session 2 injected session 1's words — cost if wrong: the protocol gained a method the batch engine barely needs.
- narrowed `load_vad`'s return annotation from `VadEngine` to `SegmentationVad` — the streaming engine needs `observe_frontier`, which ADR 0002 deliberately left off the protocol (a VAD reading its own audio has no use for it), and since ADR 0002 `load_vad` returns nothing else; the alternative was a cast at the call site that asserts the same fact less visibly — cost if wrong: a future second VAD implementation widens this annotation back.
- `update_interval = max(block_ms, 200) / 1000` rather than leaving Moonshine's 0.5 s default — measured at 200/300/500/800 ms; cadence changes how often lines update but not when the first arrives, and 200 ms costs nothing at 0.4-0.5× realtime — cost if wrong: slightly more decoder work per second than necessary on a slower machine.
- accepted that spec 10.1's 300 ms first-partial budget cannot be met (ADR 0004), took option 1 (record the real floor) and deliberately did NOT build the warm-up decoder that would fix it — spec 10.4's order is exhausted, not skipped: `update_interval` does not move the first event, compute is not the constraint (0.4-0.5× realtime), and first-event latency is identical to the millisecond across medium/small/tiny (a 2.5× cost spread), so the floor is architectural to Moonshine's streaming frontend and no model choice touches it; spec 13.3 exists so a miss this size reaches the owner as a decision rather than being absorbed by an implementation — cost if wrong: phase 2 ships with ~800 ms of blank overlay after speech onset, and the remedy (a shadow batch decoder, cost measured in ADR 0004) waits for the checkpoint.
- fixed `--replay`'s pacer, which is outside the brief's file list — Step 5 measures first-partial latency *with* `--replay`, and its deadline was relative to the end of the previous wait, so any decode burst longer than a block was added to the clip instead of caught up; a 12 s clip took 16 s and every reported latency was inflated by machine speed, which is the opposite of what its own docstring promises. Proved RED with a fake clock (800 ms of audio carrying 500 ms of bursty compute must still finish at 800 ms) — cost if wrong: one more file touched than the brief listed.

## Task 18: GTK4 overlay process and ADR 0003

- `LD_PRELOAD` is REQUIRED, not optional, and the brief named the wrong library — probed it rather than assuming either way: without a preload `is_supported()` is False on Hyprland even with `Gtk4LayerShell` imported before `Gtk` and a live `GdkWaylandDisplay`, and the brief's `/usr/lib/liblayer-shell-preload.so` leaves `is_layer_window()` False while its own shim warns three times; `/usr/lib/libgtk4-layer-shell.so` (the name in the library's own diagnostic) gives `is_supported()` True, `is_layer_window()` True, keyboard mode NONE — cost if wrong: a machine whose layer-shell package lays out its libraries differently needs the path in ADR 0003 updated.
- the overlay preloads itself by re-executing once (guarded by `FLOWD_OVERLAY_PRELOADED`) instead of the brief's plan of having the daemon set `LD_PRELOAD` when spawning — the requirement would otherwise live in the parent, where forgetting it fails *silently* (see the next ruling) and running the overlay by hand to debug it also fails; the daemon now spawns it with no special environment — cost if wrong: one `execve` at startup, before the process has done any work, and one environment variable visible to the child.
- replaced the brief's `_try_layer_shell`, which treated "no exception from `init_for_window()`" as success — measured that the call raises nothing when the preload is absent: it warns and leaves an ordinary focusable toplevel, so the brief's helper would report a working overlay and hand the user a window that swallows their dictation, which is exactly spec 5.8's worse-than-no-overlay case. The implementation now reads `is_layer_window()` back after init and the keyboard mode back after setting it, and disables itself if either disagrees — cost if wrong: two extra round-trips to the library at startup.
- rewrote the brief's import test from a substring blacklist (`"from flowd" not in source`) to an AST walk diffed against `sys.stdlib_module_names` — the property under test is that every import resolves on a bare system interpreter outside the venv, and a list of four banned names passes any dependency nobody thought to ban; the AST version fails closed — cost if wrong: a future legitimate third-party import must be added to `ALLOWED_THIRD_PARTY` explicitly.
- used `Gtk.CssProvider.load_from_string` and `Pango.EllipsizeMode.END` where the brief had `load_from_data(bytes)` and the literal `3` with a comment explaining it avoided importing Pango — probed both on GTK 4.22.5: all three loaders exist, but `load_from_data` is the pre-4.12 form, and `int(Pango.EllipsizeMode.END)` is indeed 3, so the magic number was correct and simply less readable than the import it was avoiding — cost if wrong: `Pango` must be in the typelib, which it is wherever GTK4 is.
- added `Gio.ApplicationFlags.NON_UNIQUE` to the `Gtk.Application`, which the brief did not — without it a stale overlay holding the bus name swallows the next one's activation, and the daemon waits for a preview an old session's window is quietly answering for; verified the flag exists on PyGObject 3.56.3 before using it — cost if wrong: two overlays could run at once, which the daemon's single-child lifecycle (Task 19) does not do anyway.
- reject valid JSON that is not an object (`[1,2,3]`, `"str"`, `null`) explicitly — the brief caught `AttributeError` from `message.get` alongside `JSONDecodeError`, which works by accident for a list (no `.get`) but not for a dict-shaped non-message; the reader now type-checks and logs, with those shapes in the malformed-input test — cost if wrong: none identified.

## Task 19: Overlay IPC and daemon wiring

- dropped the brief's `preload` parameter from `OverlayProcess` — ADR 0003 (Task 18) decided the overlay preloads itself by re-exec, precisely so the requirement does not live in the spawner where forgetting it fails silently, so a daemon-side `LD_PRELOAD` knob is dead weight that invites someone to set it and believe it matters — cost if wrong: a machine where self-preloading cannot work needs the variable set outside the daemon (systemd unit, wrapper) rather than in config.
- `stop` waits up to 1 s for the child to act on `quit` before signalling, where the brief sent `quit` and called `terminate()` in the same breath — measured rather than reasoned: the compositor run reported `rc=-15` on every shutdown, so the message the overlay implements and has a passing test for was never reaching it. Both halves of the protocol were tested and the seam between them was not; GTK now drops its layer surface itself instead of being cut off mid-frame — cost if wrong: up to 1 s added to daemon shutdown if an overlay hangs without dying, capped and then signalled.
- after 3 consecutive failed spawns `OverlayProcess` stops trying, and `show` resets the count, where the brief respawned unconditionally on every message — `render` runs on every STT event, ten times a second, so an overlay that dies instantly would have the daemon forking continuously and competing for the cores STT needs; `show` is the reset because a new session is the moment the user may have installed the package or moved to a layer-shell compositor, and a daemon that runs for weeks should not stay preview-less over one bad minute — cost if wrong: an overlay that fails exactly three times mid-session then recovers waits until the next `show` for its preview.
- `_ensure` checks the script exists before spawning, which the brief did not — `python3 /missing/path.py` spawns happily and exits 2, so the writes land in a pipe buffer nobody reads and the user sees no preview and no reason why; an explicit check logs the path — cost if wrong: one `stat` per session start.
- the daemon stops the overlay in `run`'s `finally`, which neither the brief nor Task 18 wired up — the child does exit when stdin closes, but only once it notices, and until then a finished session's preview sits on top of the user's work; the daemon owns the child, so it reaps it — cost if wrong: none identified; `stop` is idempotent and spawns nothing.
- `_render` splits the zones on `Chunk.resolved` rather than the brief's literal `("DONE", "FALLBACK")` / `("PENDING", "INFLIGHT")` tuples — which states count as finished is session.py's to define, and a second copy here is one to forget when phase 3 adds a state; the brief's own two tuples already disagreed about `MERGED` — cost if wrong: none identified; `visible_chunks()` already excludes `MERGED`, so the two spellings agree today.
